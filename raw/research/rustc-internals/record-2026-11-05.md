## Concrete observations

- rustc_interface/src/passes.rs wires parsing, expansion/resolution and global-context work; rustc_parse/src/parser/mod.rs is recursive-descent AST parsing. Do not claim rustc's AST is Rowan's lossless CST.
- MacroExpander::fully_expand_fragment in rustc_expand/src/expand.rs iteratively resolves/expands/integrates macro invocations. SyntaxContext/ExpnId data are implemented by rustc_span/src/hygiene.rs; source byte locations alone do not identify an expanded name's resolution context.
- rustc_ast_lowering/src/lib.rs lowers expanded/resolved AST into HIR. Body type checking lives in rustc_hir_typeck, including typeck_root/typeck_with_inspect, not a universal type_of(expr) query. Type inference may generate additional obligations; snapshots/probes roll back tentative constraints.
- rustc_trait_selection contains classic selection/fulfillment; rustc_next_trait_solver contains the next solver. The inspected next-solver module calls itself WIP and names routing controls. This capture does not establish a single globally enabled solver mode for every compilation.
- rustc_mir_build/src/lib.rs registers thir_body, check_match, check_unsafety and build_mir_inner_impl. rustc_borrowck provides mir_borrowck; rustc_mir_transform has staged MIR passes; validate.rs checks phase-sensitive CFG/types/debuginfo. Const evaluation operates through const_eval/eval_queries.rs. Monomorphization collector and codegen_ssa/base.rs connect concrete items and backend generation.
- rustc_middle/src/dep_graph/graph.rs implements try_mark_green/try_mark_previous_green, fingerprints, read edges and diagnostic-side-effect recording. Guide explains DefPathHash/stable identities and ID remapping across disk sessions. In-memory IDs cannot simply be persisted.
- rustc_span/src/source_map.rs maps byte positions to files/lines/snippets and supports remapped filenames. Hygienic span provenance and source maps are distinct from durable release telemetry identity.
- UI tests compare expected diagnostics; MIR-opt has pass-specific dumps/diffs and bit-width variants; incremental fixtures use revision markers and invalidation assertions. They are regression evidence, not a verified compiler theorem.
