# Domain contracts, architecture and evolution research

- Evans DDD Reference March2015: Bounded Context physical p9/printed2 scopes model vocabulary; Aggregates physical p23/printed16 assigns root/enforcement responsibility and aligns synchronous consistency inside versus asynchronous coordination across boundaries; Assertions physical p29/printed22 gives operation postconditions and aggregate invariants. These are design patterns, not storage/runtime guarantees.
- Eiffel tutorial: precondition is caller obligation, postcondition guarantee for valid entry, old refers to entry-state expression, invariant at externally visible stable boundaries. BEAML still validates untrusted inputs; do not import trusted-client advice as authorization to omit decoding.
- Ecto3.14.3: changeset validation differs from database constraints; optimistic lock uses a version and stale update can fail. PostgreSQL18: row checks have null/row scope, unique/FK constraints and transaction isolation/locks enforce different properties; serializable failures require retry policy. A typed pure transition alone proves none of these persistence conditions.
- Akka2.10.24 event-sourcing docs: command handling validates/emits events; event handler updates/reconstructs state and must not replay external side effects. Persistence/thenRun failure windows and single-writer assumptions are explicit. This is a precedent, not an Akka dependency recommendation (docs list BUSL-1.1).
- Avro1.12 resolution uses writer and reader schemas; fields match by name, reader defaults address absent writer fields, enum/union choice and aliases have rules. Parsing canonical form/fingerprint identifies parsing equivalence, not arbitrary business/refinement/effect/privacy compatibility. Protobuf warns against field-tag reuse, including retained historical serialized data and rollback versions.
- ArchUnit1.5.1 derives class/package dependency graphs from Java bytecode, layers/slices and cycles; its generic cycle API carries edge metadata. Empty selector failure prevents vacuous success. It does not establish information-flow safety; BEAML needs compiler symbol/effect/MIR data and explicit unknown foreign calls.

## Derived BEAML proposals

Separate pure decide/evolve/invariant checks from versioned commit/transaction/effect adapters; define failure/unknown-commit/retry/idempotency. Define compatibility per producer/consumer/direction and persisted-version set; schema representation and business migration are different checks. Architecture rules specify edge kinds, direct/transitive semantics, match counts and unknown scope. Contract evidence records status, assumptions/checker/source/build/runtime-hook/fixture/counterexample and separate release disposition; no waiver upgrades UNKNOWN to PROVEN.
