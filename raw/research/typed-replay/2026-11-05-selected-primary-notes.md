## Selected evidence

1. Temporal, Workflow Execution overview, https://docs.temporal.io/workflow-execution#replays ; selected Replay and Commands/awaitables sections. The engine re-runs workflow code and compares its generated commands with persisted history. This is a managed workflow boundary; it does not record every machine instruction or external system state. Recovery resumes from recorded history. Read through web tool, not executed.
2. Temporal, Events and Event History, https://docs.temporal.io/workflow-execution/event#activity-events ; selected Activity Events, history and limits sections. Activity retries are not each represented by a complete per-attempt stream in ordinary history: scheduled may be the only activity event until a terminal result is stored. History is bounded and Continue-As-New changes the run boundary. Read through web tool, not executed.
3. Temporal Go SDK, Side Effects, https://docs.temporal.io/develop/go/workflows/side-effects ; selected opening, correct/incorrect examples and Mutable Side Effects sections. A recorded nondeterministic result is reused during replay. Mutating captured workflow state inside the skipped callback makes replay differ. Results must carry the information needed by later deterministic code. Read through web tool, not executed.
4. Temporal, application data conversion, https://docs.temporal.io/dataconversion ; selected Data Converter, Payload and custom-codec sections. Serialization turns application values into payloads and back; custom codecs may add encryption/compression. A type tag is not validation or encryption. The page's general sensitive-data wording must not be interpreted as encryption by the default JSON converter. Read through web tool, not executed.
5. Akka core Event Sourcing, https://doc.akka.io/libraries/akka-core/current/typed/persistence.html ; observed 2.10.24, selected Introduction, Event handler, Side effects ordering/guarantees and single-writer sections. Recovery folds persisted events into state; the event handler must avoid external side effects. Post-persist callbacks are not replayed automatically, and repairs can repeat effects. Multiple concurrent writers for one persistence identity can corrupt interpretation. No Akka use proposed.
6. Clang Compiler User's Manual, https://clang.llvm.org/docs/UsersManual.html#options-to-control-clang-crash-diagnostics ; selected crash/reproducer options. A compiler reproducer includes preprocessed inputs and a run script; module reproduction can also require module/header cache inputs. A timing trace is different from reproduction input. We did not generate or inspect a crash archive; such archives can expose source and arguments.

## BEAML implications (researcher proposals)

Keep domain event recovery, deterministic workflow re-execution, retained broker-log consumption and compiler input reproduction distinct. Build two REPLAY CAPSULE profiles: language/compiler and controlled execution. Capture streams/retries at BEAML's chosen effect boundary; do not assume a workflow engine's default history is sufficient for all provider attempts and chunks. Preserve original artifacts, ordered boundary outcomes, typed-invalid inputs, policy and completeness. Keep live effects unavailable during reproduction. See maintained source/concept pages for the complete original BEAML proposal.
