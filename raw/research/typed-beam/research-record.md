# Typed languages on BEAM: selected observations

Retrieved 2026-11-05. Publishers and exact pins: [provenance](provenance.json). This is a researcher capture, not copied source or an executable conformance result. Coverage: selected Dialyzer documentation, Gleam backend/type declarations, Elixir inference/type-description implementation and official explanatory documents. Limits: no full algorithm/proof audit, release compatibility claim or runtime experiment.

Dialyzer's official model section says it may omit bugs it cannot establish. Function specification comparison checks overlap, not exact equality/subset implementation conformance. When inferred/spec types overlap it uses their intersection, trusting restrictions the user may know. Therefore a restrictive but wrong spec can affect downstream diagnostics; warning absence is not a safe-core theorem or input validator.

Gleam's pinned Erlang constructor generator uses an atom for a fieldless constructor and a tag-headed tuple for a constructor with fields. The generator separately emits Erlang type specifications, including handling phantom type variables. This concretely separates compile-time type identity and generated term representation. The official external guide/tour says foreign function annotations are trusted because the compiler cannot establish the foreign implementation's type.

Elixir's v1.20 release announcement describes inference/gradual checking without adding user annotations as its first completed milestone. It describes dynamic types narrowed by use and remaining research/development for recursive/parametric/signature work. The pinned types module documents distinct inference modes; the descriptor module uses set-theoretic representation including BDDs and static/dynamic bounds. These are current precedents for analyzing a dynamic language, not proof that arbitrary BEAML refinements/effects/labels are supplied by Elixir's compiler.

BEAML inference from these sources: generated typespecs, a conventional tuple tag, an opaque type or a phantom state parameter cannot alone stop arbitrary foreign code from forging values or leaking data. Public boundaries still need explicit schema/nominal/version checks and trusted-effect policy. Generic schema reification remains an independent design choice between specialization and explicit witnesses/dictionaries. No such ABI is adopted by this capture.
