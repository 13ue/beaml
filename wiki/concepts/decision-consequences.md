# Decision consequences for BEAML

Status: **[Proposal]**, informed by [Decision4](../sources/decision4.md).

BEAML research should distinguish an easily revised local note from choices that bind future users, other teams, or external parties. Record alternatives and consequences when proposing public language syntax, emitted artifact formats, runtime protocols, dependency licenses, or telemetry behavior. No such compatibility commitment has been implemented yet.

A useful decision note records the problem, evidence, viable alternatives, chosen option (when authorized), what it commits the project to, and the condition for revisiting it. An open research question remains open when the evidence does not settle it.

This is a documentation practice, not a new authorization or approval workflow. The [maintenance guidance](../../AGENTS.md) and current user task govern work here.
