## Evidence contracts

- **Build.** Use the original archived input for compilation and lookup. Record the parser-emitted function name and exact UTF-8 byte range. - **Live window.** Start a fresh release pair with empty observations. Record UTC before the first request and after the final flush. Send the two fixed requests in order and verify exact responses. After each request, flush and associate the receipt with the sole new Orders root. Retain the before and after counters and require a Payments delta of two and an Orders connect delta of one per receipt.
- **Query.** Match the qualified name, SOURCE ID and Payments artifact ID. Require one ended successful function span per receipt, the exact remote parent edge and clean capture. Require exactly two known receipts and two eligible successes to report 2/2. Resolve through the sealed build key and slice the verified archived input at the checked range. Compile a second fixture with changed executable behavior, the same qualified name and different source and BEAM hashes. Mark it current in the lookup context. It supplies no observations. Retain a derivative without original source and require `missing_source`.
- **Response record.** Split the Orders HTTP exchange from `decode!` at the existing raw receive boundary. The live client records its actual status and the original bounded bytes before calling the decoder. Keep the existing 200-only behavior and 1–1024 byte body limit. Seal a versioned record for the first receipt with the prepared synthetic request, trace and client span IDs, Orders artifact ID, operation, attempt, status, body length, SHA-256 and Base64 bytes. Verify the identity and bytes against same-run evidence. Use a dedicated capture file and report capture loss.
- **Decision.** The live router and replay entry call the same Orders preparation and finish functions. Finish calls the original generated finish and payment validator. Both paths call the same status and JSON decoder. Archive the actual release BEAMs for Orders decision, generated checks, HTTP decoder/transport and the support validator. Record their file hashes from the same live build. Verify every allowed module before loading it. Bind the record to the digest of this fixed module set and to the first live receipt. Use the supported runtime and load no listeners.
- **Observer.** Count the exact entry before `:gen_tcp.connect`. Reuse the probe's atomics count per release and split out counter initialization if the isolated VM needs it without installing telemetry. Increment immediately before connect in the real Orders HTTP function. Use that same path and counter in a separate bounded control VM with a known failing loopback connect. Require one observed attempt even on failure. Use a fresh zero counter for replay. Check it after the valid replay and each invalid case.
- **Controls.** Remove the saved response, change the operation and change the attempt in separate derivatives. Expect `missing_response`, `operation_mismatch` and `attempt_mismatch`. Check request and operation before substitution and before finish. Retain an explicit step result that confirms which stage ran. For operation and attempt mutations preserve the otherwise valid payload and evidence envelope so each check exposes its own divergence. Verify that all original evidence hashes stay stable.
