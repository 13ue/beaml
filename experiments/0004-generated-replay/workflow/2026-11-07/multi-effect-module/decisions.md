## OWNER questions (Migrate, built defaults)

### Q6E-1 · Migrate · big · Which sources take the module name from the file stem

- **Context.** **[Verified]** Every build is `defmodule BeamlSpike` (main.rs line 2809). Q5-6 default A: the module name comes from the stem (`orders.beaml` → `Orders`), so the host writes `Orders.ui_place(params)` (DL-131).
- **Option A.** Every source with a lowercase identifier stem. Challenge: every generated byte moves; the four pin sites, `cli.rs` 262 to 264, the three `defmodule BeamlSpike do` rename sites (0004 `run.py` 279, 0002 `run.py`, 0003 tests), `DRIVER` and about 250 test lines change; stems such as `order-flow` and `payments.applied` need a fallback rule. Needs the re-pin sub-step of [plan.md](plan.md#byte-pins-two-options-one-default-q6e-1).
- **Option B (from the brief).** The stem unless the file name holds `spike`. **[Observed]** No tracked source has `spike` in its name, so B equals A. Not built.
- **Option C (default).** The stem only for a source with an ENTRY LINE (a host-called module); every other source stays `BeamlSpike`. Blast radius: the three `slice6/entry` fixtures and `slice6_entry_test.py`; no pin site moves. Challenge: two rules for one name; a source renames its module when it gets its first ENTRY LINE.
- **Option D.** A `module Orders` line (Q5-6 B). Already open as Q5-6 B; not re-asked here.
- **Derivation.** One capital per `_` segment: `orders` → `Orders`, `order_flow` → `OrderFlow`.
- **Why Migrate.** Host code calls the module name (0005 `OrderFormLive`); a change later rewrites every host call.
- **Interim.** C is built. A later step can move to A with the re-pin sub-step; the host calls stay the same for ENTRY LINE sources.
- → By: Opus (PLAN multi-effect, default, open)

### Q6E-2 · Migrate · big · The namespace of `Rejected`

- **Option A (default).** `<Module>.Rejected` (`Orders.Rejected`). **[Verified]** `defmodule Rejected` is nested, so it moves with the module; no code beyond Q6E-1. Matches the 0005 plan host match `{:error, %Orders.Rejected{reason: r}}`.
- **Option B.** One fixed top-level `BeamlSpike.Rejected` (or `Beaml.Rejected`) for every source. Challenge: two generated sources in one host build define the same module two times; it needs a separate emitted module outside `<Module>`.
- **Why Migrate.** Host code matches on the struct (DL-133).
- → By: Opus (PLAN multi-effect, default, open)

### Q6E-3 · Migrate · The REPLAY RUN call with several EFFECTS

- **Option A (default).** With two or more EFFECTS: `Replay.run(operation, a0, trace_id, records)` and `Replay.record(operation, request, status, bytes)`, one clause per EFFECT; an unknown operation gives `{:error, :operation_mismatch}`. With one EFFECT: today's `run/3` and `record/3` (bytes stay). `Replay.entry/2` picks the flow by the ENTRY RECORD operation.
- **Option B.** `run/3` everywhere: it selects the record by `trace_id` and runs the flow of the record's `operation`. Challenge: the caller cannot say which flow it means; an `a0` of another TYPE enters the public wrapper of another flow, which raises `ArgumentError` (a REPLAY RUN that raises).
- **Option C.** One nested module per EFFECT (`Orders.Replay.StockReserve.run/3`). Challenge: more modules; `@parent` needs another rule.
- **Why Migrate.** Test harnesses and later host tools call `Replay`. No 0005 host code calls it, so it is not big.
- → By: Opus (PLAN multi-effect, default, open)

### Q6E-4 · Migrate · One EFFECT per flow

- **Context.** **[Verified]** No check stops one pipe that calls two EFFECTS; the one-EFFECT check hid it. `select/2` needs one RESPONSE RECORD per trace. The 0005 plan row P3 says "`Replay` selects by operation".
- **Option A (default).** A pipe calls at most one EFFECT: `error: fn <f> calls the effects <a> and <b>; slice 6e replays a flow with one effect`. "Selects by operation" means the flow (Q6E-3), not the record inside one trace. Enough for the 0005 source (`place` → `orders.save`, `list_orders` → `orders.list`).
- **Option B.** A pipe may call several different EFFECTS, each once; `select(records, trace_id, operation)`. Challenge: a record of the wrong operation then gives `missing_response`, not `operation_mismatch` (an existing reason changes); every EFFECT source changes bytes (the four pins move).
- **Why Migrate.** It limits what the 0005 source can say: `place` cannot authorize a payment and then store the order in one flow.
- → By: Opus (PLAN multi-effect, default, open)

## Undo and Repair defaults

Chose: remove `slice 1 supports one effect` and the D6B-147 `index > 0` check; add the Q6E-4 A check. Every other EFFECT and ENTRY LINE check runs per line as today. Over: a fixed maximum. Because: the lists exist; the checks are per line already. Commits us to: one flow per EFFECT and one EFFECT per flow.
By: Opus (PLAN multi-effect)

**D6B-198 · Repair · Shared defs and modules are written once.**
Chose: one name set in `emit`; `__beaml_attempt__`, `BeamlFailure`, `Http`, `__beaml_redact__`, the failure structs and each decode helper def go out at their first place and are skipped later. Over: a compile error for shared TYPES; a full split of `emit_effect`. Because: 0005 shares `Amount` and `Channel` between the input and output TYPES; a one-EFFECT source writes nothing two times, so its bytes stay (N13). Commits us to: helper names stay a function of the TYPE name only.
By: Opus (PLAN multi-effect)

**D6B-199 · Repair · One `Replay` module; two shapes by EFFECT count.**
Chose: `Replay` after the EFFECT loop; Q6E-3 A clauses from two EFFECTS; the one-EFFECT form unchanged. Over: the new shape for every source (moves the four pins). Because: smallest blast radius. Commits us to: two shapes until a re-pin step joins them (`ponytail:` comment at the branch).
By: Opus (PLAN multi-effect)

**D6B-200 · Repair · `entry/2` and `entry_record/3` dispatch on the operation.**
Chose: one `entry/2` clause per ENTRY LINE that targets a flow, on `%{"operation" => op}`, a last clause `{:error, :operation_mismatch}`; `entry_record(operation, bytes, decoded)`. For every ENTRY LINE source. Over: the slice 6d `expect` form for one ENTRY LINE. Because: ENTRY LINE sources are not pinned and move with Q6E-1 C anyway; one shape is less code. Commits us to: the reason order operation, digest, decode stays.
By: Opus (PLAN multi-effect)

**D6B-201 · Undo · Two ENTRY LINES with one operation give `duplicate name: ui_<op>`.**
Chose: the existing text, now also between ENTRY LINES. Over: a new text. Because: the generated function name is what collides.
By: Opus (PLAN multi-effect)

**D6B-202 · Undo · No check of the UI EVENT string.**
Chose: two ENTRY LINES with one `ui.event("e")` string compile. Over: a duplicate-event check. Because: **[Verified]** the parser does not keep the string; the host clause picks the call. Limit recorded.
By: Opus (PLAN multi-effect)

**D6B-203 · Undo · Reserved module names.**
Chose: a compile error when the stem gives a module that the generated code calls (`Kernel`, `String`, `Enum`, `Map`, `List`, `IO`, `Base`, `Module`, `Code`, `Integer`, `OpenTelemetry`, `ProbeSupport`, `ArgumentError`): `error: the source file name <stem> gives the module <M>, which the generated code calls; rename the file`. Over: no check; a namespace prefix (contradicts `Orders.ui_place`). Because: `defmodule Enum` would break the generated code itself.
By: Opus (PLAN multi-effect)

**D6B-204 · Undo · `DRIVER` reads the module name from its input.**
Chose: the key `"name"` beside `"module"`; `Module.concat([name])`; match `[^name, failure]`. Over: a text replace of `BeamlSpike` in `DRIVER`. Because: one driver for every module name; no generated byte changes.
By: Opus (PLAN multi-effect)

**D6B-205 · Undo · fmt aligns adjacent EFFECT lines and ENTRY LINES as one group.**
Chose: no fmt change (existing `aligned`, R6D-06). Over: one group per direction. Because: the code already does it; N11 pins it.
By: Opus (PLAN multi-effect)

**D6B-206 · Undo · `--stored`, DEAD LINES and DL-040 need no code change.**
Chose: pin the per-operation behaviour with N7 to N9. Over: new code. Because: **[Verified]** every check keys on the operation; orphans give one block per operation with its own count; `oldest` takes the minimum over operations.
By: Opus (PLAN multi-effect)

**D6B-207 · Undo · Two ENTRY LINES may target one flow.**
Chose: allowed; `entry/2` has one clause per ENTRY LINE. Over: a compile error. Because: no check needs it; nothing breaks.
By: Opus (PLAN multi-effect)

**D6B-208 · Undo · Fixture `slice6/multi/orders.beaml` with `stock.reserve` and `ui.hold`.**
Chose: a second http EFFECT whose output `Hold` holds `Amount`, and a second ENTRY LINE with the same input TYPE. Over: a `db` EFFECT (P4, not built). Because: it exercises D6B-198 with the only transport that exists.
By: Opus (PLAN multi-effect)

**D6B-209 · Repair · P3 and P5 in one step.**
Chose: one ledger for both. Over: two steps (the 0005 order P3 → P5). Because: both change the module layout (`emit` header, `Replay`, `DRIVER`, `slice6_entry_test.py`); two steps would edit the same test lines two times. Commits us to: one RED covers N1 and N14.
