## 2. a2a: record format draft 4 (DL-168, DL-165)

### Shape (built default; OWNER sign needed before a2a GREEN, DL-139)

```
"version": 4,
"type": {"name": "Order", "version": 1, "fields": [...], "fingerprint": "...",
         "nested": {"amount": 1, "channel": 1}}
```

- `nested` maps a direct field name to the TYPE VERSION of its TYPE. Only fields whose TYPE has a constructor or is an enum
  (the `ctor_fields` and `literal_fields` lists). Always present; `{}` for a TYPE without such fields.
- The writer knows it at compile time: every value that the current build writes is at the newest nested version.
  So `nested` is a constant in `emit_type_key` and `emit_type_version`. No run-time cost.
- The key is the field name of the written TYPE VERSION. A later `rename` is undone by `stored_key` (DL-166).
- `fingerprint` and `value_sha256` do not cover `nested` (same as `name`, `version` and `fingerprint` today).
  This keeps P2b's digest code untouched.
- Reader: `--stored` reads version 4 only (three sites). A version 4 core without `type.nested`, or with a non-integer
  value, is `malformed TYPE VERSION`. There are no production stores yet (DL-165), so there is no v3 fallback.

### Write side (generated Elixir)

- `version: 3` → `version: 4` in three writers: `Replay.record` (responses), `entry_record` (entries), `DB_HELPERS` `db_core`
  (rows and db call records). This moves the bytes of every EFFECT source.
- `emit_type_key` and `emit_type_version` gain `nested: %{...}`.
- The generated readers (`row_<t>`, `decode(bytes, type_version)`) match maps and ignore extra keys. No change in a2a.

### Read side (`--stored`, Rust)

- The version checks for ENTRY RECORDS, RESPONSE RECORDS and ROWS (`n == "3"`) become `"4"`. The three texts
  `this build reads record version 3 only (DL-143)` become `… version 4 only (DL-168)`.
- The `StoredVersion` parse reads `nested` into a map.
- **SQUASH block (GF-11).** If a stored nested version is not a version that the source declares for that TYPE, the build
  blocks. Default text:
  `error: stored ROW holds Channel v1 in field channel; the source declares no Channel v1. Keep enum Channel v1 and migrate Channel v1 -> v2 while v1 values are stored (SQUASH, DL-155)`.
  It is one check in the reader, so it belongs in a2a, not fates-b. The note "no v1 value is left, the step may leave"
  goes to fates-b with the DEAD LINE rule for fate steps.
- **Fate selection by version.** A fate line in `migrate X vA -> vB` acts only on stored values whose nested version for
  `X` is below `vB`. A stored v2 `Amount` that fails the v2 rule is not quarantined; it blocks (DL-102). This replaces
  the a1 rule of "today's rule for every value" (QF-2 A, built in a1).
- **GF-02.** The swap check reads the table of the stored nested version, not the `from` table of the last step. The RED
  worker first checks that a1 builds an enum chain with two steps (V4h). If a1 rejects such a chain, V4h becomes a
  recorded exclusion and GF-02 goes to fates-b.

## 3. a2b: fate lines at run time (DL-157, DL-162, DL-172)

Only row TYPES and decodes with a fate line change bytes (PF-16). Shared constants (`DB_HELPERS`, `SELECT`, `body`) stay.

- **Constructor quarantine (DL-172).** The generated `__beaml_from_C` returns `:quarantined` instead of `:constructor` when
  two things are true. First, the failing clause tests a quarantined parameter. Second, the stored nested version of `C` is
  below the step's `to`. The clause test is a generated clause chain `__beaml_parked_C(args)` with one clause per
  `fn C` clause, in clause order, each `true` or `false`. The same Rust function feeds `tested_params` (the help) and this
  chain, so the help and the run-time lift cannot differ (QB-2, a1b O3).
- **Literal quarantine (DL-162).** `quarantine "fax"` (enum step) or `quarantine channel "fax"` (owner step) sets the raw
  value to `:quarantined` before the literal map. Gate: older nested version (bare form) or the chain guard (owner form).
- **Tail order.** `:constructor` first, then a decode `:error`, then `:quarantined` → `{:error, "quarantined"}`. A row with
  a fault and a parked value still fails (R1b).
- **Bare `map "old" -> V`.** The literal function of `E` takes the nested version. It maps `"old"` only for a stored version
  below the step's `to`. Live input (no `type_version`) uses the newest table, so `"old"` is not an alias (DL-168 over the
  QF-2 A risk). Encode of `V` writes V's own literal.
- **Qualified `map f "old" -> V`.** One more line in the chain-step `changes` (the existing `guard`): put V's literal when
  the raw value is `"old"`.
- **`rows_<t>`.** Skips `{:error, "quarantined"}` and counts. Any other error still fails the list (QDB-4).
- **`list_`** (row TYPE with a quarantine line only): returns `{:ok, value, %{quarantined: n}}` and sets the span attribute
  `quarantined`. The accepted call record holds `quarantined: n` (QA2-2). The REPLAY RUN returns the same three-tuple from
  the record.
- **`get_`** of a parked row: `{:error, %Failure{reason: "quarantined"}}` and a `rejected` / `quarantined` call record. It
  reuses `failed()` (DL-157 "typed not-found with reason quarantined").
- **REPLAY RUN.** A RESPONSE RECORD or ENTRY RECORD whose value decodes to `{:error, "quarantined"}` gives
  `{:error, :quarantined}`. The flow does not run. A list record with one parked item is parked whole (PF-17).
- **No per-row records.** `select` needs one record per trace (`[record]`, else `missing_response`). One record per
  skipped row would break the REPLAY RUN of every list call.
- **Stop lines go.** The `hit(" quarantined by ")` / `hit(" mapped by ")` block at the end of `--stored` and its two
  texts are deleted. The GF-09 `ponytail:` at the emit site goes.
- **0005 (old a3).** `variants/stricter/` becomes the `amount_v2` form; new `variants/stricter_v1/` keeps N8 and N8b; new
  `variants/channel_v2/`; `fate_test.exs` N9 and N9b; `Orders.ui_orders/1` handles the three-tuple; `run.py` `BLOCKED`
  becomes empty and EXPECTED gains N9b. N9 reads `<run>/n-tests/<n>-n9/build.stderr` (fates plan repair 7).

**DL-158 / N9 answer:** a2a does not unblock N9. a2b does: N9 needs the list skip. N9 lands inside a2b GREEN.

### O1 (high): accepted, list fields keep nested versions

- A LIST field `items: [Order]` holds an object for its element TYPE in `type.nested`. One entry per field:
  `{"version": <element TYPE VERSION>, "nested": <the element TYPE's own nested map>}`.
- Exact shape of the db.list call record of `orders.list` (`OrderList`):
  ```
  "type": {"name": "OrderList", "version": 1, "fields": [["items", "[Order]"]], "fingerprint": "...",
           "nested": {"items": {"version": 1, "nested": {"amount": 1, "channel": 1}}}}
  ```
- A direct constructor or enum field keeps an Int: `"amount": 1`. A TYPE with no such field has `"nested": {}`.
- The writer knows all of it at compile time (newest versions), so it stays a constant beside `emit_type_key`.
- R5, R6 (a2b) and V4g (a2a) read the element versions from this object; no reader guesses a version. A missing entry,
  an entry of the wrong kind or a version below 1 is a malformed TYPE VERSION (V4e).
