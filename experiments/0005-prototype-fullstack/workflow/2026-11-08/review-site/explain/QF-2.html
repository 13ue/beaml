Zeile = Eintrag in der Postgres-Tabelle (der echte Zustand). Record = Aufzeichnung eines Aufrufs für Prüfung, Replay und Observability. Beide tragen heute denselben Kern mit type.

// VORHER: Amount steckt in Order. Beide v1.
type Amount {
  value: String
  currency: String
}

fn Amount value: String, currency: String -> Amount ! BadAmount
fn Amount _,     ""       -> Amount ! BadAmount = BadAmount {}
fn Amount value, currency -> Amount ! BadAmount = Amount { value: value, currency: currency }

type Order {
  order_id: String
  amount: Amount
  channel: Channel
}

So sieht eine Zeile heute aus (Kern, gekürzt)

{ "type": { "name": "Order", "version": 1 },
  "value": { "order_id": "o-1", "amount": { "value": "0", "currency": "EUR" }, "channel": "web" } }
// NACHHER: nur Amount ändert sich (value nicht "0"), 2 Zeilen betroffen: Amount v2 (DL-155).
// Order selbst ändert sich nicht. Welche Version steht jetzt in der Zeile?
type Amount v2 {
  value: String
  currency: String
}

migrate Amount v1 -> v2 {
  quarantine value
}

fn Amount value: String, currency: String -> Amount ! BadAmount
fn Amount _,     ""       -> Amount ! BadAmount = BadAmount {}
fn Amount "0",   _        -> Amount ! BadAmount = BadAmount {}
fn Amount value, currency -> Amount ! BadAmount = Amount { value: value, currency: currency }

type Order {
  order_id: String
  amount: Amount
  channel: Channel
}

Option A · Version nur in der Quelle (gebaut)

{ "type": { "name": "Order", "version": 1 },  // unverändert, alte und neue Zeilen sehen gleich aus
  "value": { … "amount": { "value": "0", "currency": "EUR" } … } }
ProblemEine Zeile von gestern (Amount v1) und eine von heute (Amount v2) sagen beide „Order v1“. Der Build weiß nicht, welche Regel amount bestanden hat. Das geht nur, wenn jede Amount-Änderung auch Order v2 erzwingt (Regel: eine verschachtelte Version hebt die äußere mit).

Option B · verschachtelte Versionen stehen mit in der Zeile

{ "type": { "name": "Order", "version": 1, "nested": { "amount": 2, "channel": 1 } },
  "value": { … } }
WirkungJede Zeile sagt genau, welche Regel jedes Teilwerts galt. Order bleibt v1, Amount wandert allein. Preis: Record-Format wächst um einen Schlüssel (Entwurf 4), Digest und Leser ändern sich einmal.
Option A' · wie A, aber die äußere Version springt mitAmount v2 erzwingt type Order v2 und migrate Order v1 -> v2 {} (leer). Kein Formatwechsel, aber jede innere Änderung produziert äußere Versionen und leere migrate-Blöcke; bei tief verschachtelten TYPES viele.
