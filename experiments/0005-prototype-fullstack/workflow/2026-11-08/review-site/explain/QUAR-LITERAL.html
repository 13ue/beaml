Sperre 2 (DL-122): ein gespeichertes Literal gibt es im Code nicht mehr. Ohne Fate-Zeile blockt der Build.

// VORHER: Channel komplett. In Production: 5 Bestellungen mit channel = "fax".
enum Channel {
  Web = "web"
  App = "app"
  Fax = "fax"
  Unknown(String)
}

Option A · nur map (wie in der RED)

// Option A: Fax weg. Die 5 Zeilen bekommen per map eine neue Bedeutung. Nur map löst Sperre 2.
enum Channel v2 {
  Web = "web"
  App = "app"
  Unknown(String)
}

migrate Channel v1 -> v2 {
  map "fax" -> Unknown
}
VerhaltenAlle 5 Zeilen bleiben sichtbar: auf /orders steht bei ihnen Unknown("fax"). Du könntest auch map "fax" -> Web schreiben. Die Zeile wird umgedeutet, nie versteckt. Build: „fate: 5 rows of Channel v1 mapped (fax)“.

Option B · quarantine zusätzlich erlaubt

// Option B: Fax weg. Die 5 Zeilen werden geparkt statt umgedeutet. quarantine auch auf einem Literal.
enum Channel v2 {
  Web = "web"
  App = "app"
  Unknown(String)
}

migrate Channel v1 -> v2 {
  quarantine "fax"
}
VerhaltenDie 5 Zeilen verschwinden von /orders und werden gezählt (DL-157), wie bei einer gebrochenen Regel. Sinn: du willst sie weder umdeuten noch zeigen, sondern erst anschauen. Build: „fate: 5 rows of Channel v1 in quarantine (fax)“.
Der Unterschied in einem SatzA sagt: ein Literal hat immer eine Bedeutung, notfalls Unknown. B sagt: ein Literal darf auch „noch unklar, parken“ sein, wie ein Wert, der eine Regel bricht.
