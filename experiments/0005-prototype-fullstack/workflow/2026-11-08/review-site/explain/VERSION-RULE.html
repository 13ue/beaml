Jeder Block ist in sich vollständig: TYPE, Konstruktor, migrate. Der Build prüft live gegen die Datenbank (DL-151).

Beispiel 1 · Konstruktor-TYPE Amount

// VORHER: Amount komplett, so wie heute in orders.beaml (v1, ohne Mark)
type BadAmount {}
type Amount {
  value: String
  currency: String
}

fn Amount value: String, currency: String -> Amount ! BadAmount
fn Amount _,             ""               -> Amount ! BadAmount = BadAmount {}
fn Amount value,         currency         -> Amount ! BadAmount = Amount { value: value, currency: currency }
Fall 1 · der Build findet keine Zeile mit value "0"Grün. Keine neue Version. Nur die neue Klausel:
// NACHHER, Fall 1: neue Regel (value nicht "0"), keine Zeile betroffen. Nur die neue Klausel.
type BadAmount {}
type Amount {
  value: String
  currency: String
}

fn Amount value: String, currency: String -> Amount ! BadAmount
fn Amount _,             ""               -> Amount ! BadAmount = BadAmount {}
fn Amount "0",           _                -> Amount ! BadAmount = BadAmount {}
fn Amount value,         currency         -> Amount ! BadAmount = Amount { value: value, currency: currency }
Fall 2 · der Build findet 2 Zeilen mit value "0"„2 rows of Amount v1 fail the v2 rule; declare type Amount v2 and a fate.“ Erst damit grün:
// NACHHER, Fall 2: dieselbe Regel, 2 Zeilen mit "0" in Production. Version und Fate erzwungen.
// (Form aus DL-125, nicht gebaut)
type BadAmount {}
type Amount v2 {
  value: String
  currency: String
}

migrate Amount v1 -> v2 {
  quarantine value
}

fn Amount value: String, currency: String -> Amount ! BadAmount
fn Amount _,             ""               -> Amount ! BadAmount = BadAmount {}
fn Amount "0",           _                -> Amount ! BadAmount = BadAmount {}
fn Amount value,         currency         -> Amount ! BadAmount = Amount { value: value, currency: currency }

Beispiel 2 · Enum Channel, ein Literal verschwindet

// VORHER: Channel komplett, wie heute
enum Channel {
  Web = "web"
  App = "app"
  Unknown(String)
}
Fall 1 · keine Zeile mit "app"Grün, bleibt v1:
// NACHHER, Fall 1: App weg, Mobile neu, keine Zeile mit "app". Nur die Tabelle ändert sich.
enum Channel {
  Web = "web"
  Mobile = "mobile"
  Unknown(String)
}
Fall 2 · 5 Zeilen mit "app"„5 rows carry Channel v1 "app", no literal in v2; declare map.“ Erst damit grün:
// NACHHER, Fall 2: dieselbe Änderung, 5 Zeilen mit "app". Version und map erzwungen.
// (Vorschlag, nicht gebaut)
enum Channel v2 {
  Web = "web"
  Mobile = "mobile"
  Unknown(String)
}

migrate Channel v1 -> v2 {
  map "app" -> Mobile
}

Beispiel 3 · Enum Channel, Literale vertauscht (DL-140)

// VORHER
enum Channel {
  Web = "web"
  App = "app"
  Unknown(String)
}
Fall 1 · keine ZeilenTippfehler-Fix: Literale einfach tauschen, bleibt v1, kein migrate.
Fall 2 · Zeilen vorhandenGestern hieß "web" Web, heute hieße es App. Build blockt bis beide map-Zeilen da sind:
// NACHHER, Fall 2: Literale vertauscht, Zeilen vorhanden. Beide Richtungen ausdrücklich.
// (Vorschlag, nicht gebaut)
enum Channel v2 {
  Web = "app"
  App = "web"
  Unknown(String)
}

migrate Channel v1 -> v2 {
  map "web" -> App
  map "app" -> Web
}
