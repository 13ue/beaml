In Production: 2 Zeilen mit leerem Body-Text. Der Build sieht den Wert nicht, die Datenbank hat ihn.

// VORHER: der geheime Text hat einen eigenen TYPE mit Konstruktor (DL-160). v1 ohne Mark.
type BadBody {}
type Body { text: String }
fn Body text: String -> Body ! BadBody
fn Body text         -> Body ! BadBody = Body { text: text }

type Note {
  body: redacted Body
  tag: String
}

Regel wird strenger

// NACHHER: Body bekommt die Regel "nicht leer". Das ist Body v2 (DL-155). Note bleibt, wie es war.
// Der Build prüft keine Regel über alte body-Werte: er sieht sie nicht und muss es nicht.
// Er prüft nur: hat jede Body-v1-Zeile eine Fate? Ja: quarantine. (Form aus DL-125, nicht gebaut)
type BadBody {}
type Body v2 { text: String }

migrate Body v1 -> v2 {
  quarantine text
}

fn Body text: String -> Body ! BadBody
fn Body ""           -> Body ! BadBody = BadBody {}
fn Body text         -> Body ! BadBody = Body { text: text }

type Note {
  body: redacted Body
  tag: String
}
Build„2 rows of Body v1 wait in quarantine (text)“. Grün. Auf /notes fehlen die zwei, gezählt (DL-157). Keine Regel läuft über einen fehlenden Wert, also hat redact nie etwas zu überspringen: M3 = A.

Was DL-160 ausschließt

// VERBOTEN (DL-160): ein geschwärztes Feld ohne eigenen TYPE. Build-Fehler.
type Note {
  text: redacted String
  tag: String
}
Build„field text: a redacted field needs a constructor TYPE (DL-160)“. Ohne TYPE gäbe es keine Version und keine Regel, über die man etwas über alte Werte sagen könnte.
