Es geht nur um den Wortlaut des Fehlers. Dass es ein Fehler ist, ist QM4-4 (Default: ja, bis die Fate-Formen da sind).

// VORHER: Order komplett (v1, ohne Mark), gespeichert über orders.save
enum Channel {
  Web = "web"
  App = "app"
  Unknown(String)
}

type Order {
  order_id: String
  amount: Amount
  channel: Channel
}

effect orders.save Order -> Order ! StoreError = db.put("records")
// NACHHER: du willst das Feld channel in source umbenennen. Zeilen mit channel liegen in Production.
// rename auf ein Enum-Feld ist heute ein Compile-Fehler (QM4-4), bis die Fate-Formen da sind.
enum Channel {
  Web = "web"
  App = "app"
  Unknown(String)
}

type Order v2 {
  order_id: String
  amount: Amount
  source: Channel
}

migrate Order v1 -> v2 {
  rename channel -> source
}

effect orders.save Order -> Order ! StoreError = db.put("records")

Option A · Text am EFFECT, nennt den Grund (gebaut)

error: effect orders.save: migrate Order v1 -> v2: rename channel -> source names the enum field Order.channel; a MIGRATE STEP on an enum or constructor field waits for the fate forms (M3, DL-152)
  help: remove rename channel -> source from the MIGRATE STEP
Liest sich„Welcher EFFECT ist betroffen, welcher Schritt, welches Feld, warum, was tun.“ Ein Fehler pro EFFECT, der den TYPE liest.

Option B · Text am Schritt, wie in Slice 3

error: migrate Order v1 -> v2: rename channel -> source: channel is an enum field
  help: remove the step
Liest sichKürzer, ohne EFFECT und ohne Grund. Steht einmal, egal wie viele EFFECTS den TYPE lesen. Der Leser muss M3/DL-152 selbst kennen.
Warum es dir vorgelegt wirdFehlertexte sind Teil der Sprache, die ein Nutzer sieht (DL-139). Der Default A ist gebaut und von vier Tests gepinnt; B hieße Text ändern und Tests nachziehen.
